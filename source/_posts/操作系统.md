### 第一章 计算机系统概述

1. 操作系统是什么：

操作系统(Operating System, OS)是指控制和管理整个计算机系统的硬件与软件资源，合理地组织、调度计算机的工作与资源的分配，进而为用户和其他软件提供方便接口与环境的程序集合。

2. 并发指的是同一个时间间隔内有多个事件发生，而并行指的是同一时刻多个事件发生。所以可以理解为，并发是宏观上多个程序一起执行，微观上一个时间点只有一个程序在执行；并行是宏观上多个程序一起执行，微观上多个程序在同时执行。

3. 操作系统中共享的资源主要分为两种：1. 互斥共享方式 2. 同时访问方式（P02）

4. 操作系统的发展历程：

- 手工操作阶段，所有工作都需要人工干预，虽然是用户独占全机，但是资源利用率低，而且 CPU 需要手工操作，CPU 的利用不充分。
- 批处理操作系统（操作系统开始出现），又分为单道批处理系统和多道批处理系统。
    单道批处理系统：系统对作业是成批处理的，但是内存中始终保持一道作业。单道批处理系统中，每次主机内存中仅保存一道作业，每次在运行时，发出输入、输出请求，高速的 CPU 需要等待低俗的 IO 完成操作。
    多道批处理系统：多道程序设计技术允许多个程序同时进入内存并允许它们在CPU中交替地运行。当一道程序因I/O请求而暂停运行时，CPU便立即转去运行另一道程序。
    多道程序设计的特点是多道、宏观上并行、微观上串行。
    多道程序设计的缺点：不提供人机交互能力，用户既不能了解自己的程序的运行情况，又不能控制计算机。
- 分时操作系统，指把处理器的运行时间分成很短的时间片，按时间片轮流把处理器分配给各联机作业使用。分时操作系统是指多个
用户通过终端同时共享一台主机，这些终端连接在主机上，用户可以同时与主机进行交互操作而互不干扰。所以说，分时操作系统解决了人机交互的问题，
- 实时操作系统，为了能在某个时间限制内完成某些紧急任务而不需要时间片排队，诞生了实时操作系统。
- 个人操作系统

5. 特权指令：不允许用户直接使用的指令，如I/O指令、置中断指令，存取用于内存保护的寄存器、送程序状态字到程序状态字寄存器等的指令

非特权指令：不能直接访问系统中的软硬件资源，仅限于访问用户的地址空间

CPU 处于核心态，此时 CPU 可以执行特权指令，切换到用户态的指令也是特权指令。

6. 原语是一些可以被调用的公用小程序，通常运行时间都较短，而且调用频繁。

7. 系统调用：用户程序想要获得操作系统中的资源

系统中的各种共享资源都由操作系统统一掌管，因此在用户程序中，凡是与资源有关的操作（如存储分配、进行I/O传输及管理文件等），都必须通过系统调用方式向操作系统提出服务请求，并由操作系统代为完成。

系统调用的相关功能需要使用某些特权指令才能完成，所以系统调用的处理需要由操作系统内核程序负责完成，要运行在核心态

8. CPU 通常执行两种不同类型的程序：操作系统内核程序 和 用户程序。

9. 当需要管理程序服务时，系统则通过硬件中断机制进入核心态。（需要中断，切换 CPU 的模式）

10. 若程序的运行由用户态转到核心态，则会用到访管指令，访管指令是在用户态使用，所以它不是特权指令。

11. CPU运行上层程序时唯一能进入这些 “门（指的是切换 CPU 模式）” 的途径就是通过中断或异常。

12. 从操作系统内核架构来划分，可以分为宏内核和微内核。

宏内核：将系统的主要功能模块都作为一个紧密联系的整体运行在核心态，从而为用户程序提供高性能的系统服务。因为各管理模块之
间共享信息，能有效利用相互之间的有效特性，所以具有无可比拟的性能优势。

微内核：是指将内核中最基本的功能保留在内核，而将那些不需要在核心态执行的功能移到用户态执行。微内核结构将操作系统划分为两大部分：微内核和多个服务器只有微内核运行在内核态，其余模块都运行在用户态，一个模块中的错误只会使这个模块崩溃，而不会使整个系统崩溃。

13. 操作系统的三个要求：（大概可以理解为，从多道程序设计开始，我们允许多个程序统一放入内存，就有了这些需求）

- Multiplexing 多任务
- Isolation 隔离
- Interaction 交互

14. 计算机系统（注意，这里不是操作系统）从下到上可以分为四个部分：硬件、操作系统、应用程序和用户。

所以，从这里我们可以看出来操作系统的作用：操作系统管理各种计算机硬件，为应用程序提供基础，并充当计算机硬件与用户之间的中介。

15. 内部异常处理后返回到发生异常的指令继续执行 （错误的），这是因为多数异常指示的是程序中存在一些严重的错误或不当的操作，直接返回并重新执行同一条指令往往会再次触发同样的异常，导致程序陷入无限循环。

16. OS must ensure that an incorrect (or malicious) user program cannot cause OS and other programs to execute incorrectly？

操作系统必须保证一个错误的（或者恶意的）用户程序不能导致操作系统和其他程序执行不正确，这个是通过「特权指令」来实现的，不允许在用户程序直接执行这些特权指令，只有OS内核才可执行这些特权指令。

我们将一些可能对于系统造成伤害的指令设计为特权指令，只有操作系统内核才能执行这些指令，用户程序不能执行这些指令，比如对于 IO
、Timer、Interrupt、Memory 的操作。

17. 如何保证特权指令不能在用户程序中执行？OS无法实现，应该由CPU来完成，所以我们设计了两种模式：用户态和核心态。（注意这一部分的逻辑，不产生危害 -> 特权指令 -> 如何实现？OS不行，使用CPU -> 设计 CPU 的两种模式

如果在用户态执行特权指令，将出错，并陷入到核心态由操作系统处理

18. 如果用户程序需要完成只有特权指令才能完成的操作，如何处理？

用户程序通过系统调用（system call）请求操作系统来完成
当执行系统调用时，操作系统将运行在核心（系统）模式

23. 中断分为硬中断和软中断两类，也可以分为外中断和内中断两类（这里的内和外是针对于 CPU 而言的，内中断是发生在 CPU 内部的异常，外中断则是 CPU 外部的硬件设备提出的中断）。

故障异常和自陷异常属于软件中断（程序性异常），终止异常和外部中断属于硬件中断。也就是硬件中断程序性中断的划分和硬中断、软中断是不一样的。

24. 其中，软中断也就是异常可以分为：故障（Fault）、陷阱（Trap）、中止（Abort）。

故障是由于程序执行中发生了错误或异常条件而产生的。例如，当程序尝试访问无效的内存地址时，会发生页面故障（page fault）。故障通常可以被修复，一旦修复，程序可以从故障发生的地方继续执行。

陷阱是程序执行中有意产生的中断，通常用于调试目的或执行系统调用。陷阱在执行完相关指令后立即触发，并且通常预期中断返回到下一个指令继续执行。

中止是在发生严重错误时产生的，这种错误通常是不可恢复的（和故障 Fault 之间的区别），比如硬件故障或者系统的内部一致性错误。中止通常意味着程序无法继续执行。

25. 硬中断通常需要快速响应，因为它们涉及到硬件设备的即时数据处理；软中断是由操作系统内核产生的中断，不直接由硬件触发，通常用于处理不那么紧急的任务，例如，当操作系统需要执行后台任务或处理已经在硬中断处理程序中接收到的数据时，它可以使用软中断来延后处理这些工作，以避免阻塞硬中断处理。

（注意这里的分类，软中断包括故障异常和自陷，但是硬中断包括终止故障和外中断）

所以，对于软中断发出的请求，CPU 通常不是立即执行的，而是根据操作系统的调度策略和当前的系统负载情况延迟处理。

26. API 是 a set of functions that are available to an application programmer，比如说 C 语言的标准函数库为用户提供的就是 API 接口，所以我们为什么一般更爱使用 APIs 而不是 System Call？

- 首先因为移植性，System Call 通常是基于某一个特定的操作系统的，而 API 则是基于某一个编程语言的，所以 API 更加容易移植。
- API 的使用一般来说更方便、封装更好（毕竟 API 是机遇某一个特定的操作系统下的 System Call 实现的）。

### 第二章 进程与线程

1. 在多道程序环境下，允许多个程序并发执行，此时它们将失去封闭性，并具有间断性及不可再现性的特征，因此我们引入了进程的概念。

2. 系统利用PCB来描述进程的基本情况和运行状态，进而控制和管理进程。

3. 程序段、相关数据段和PCB三部分构成了进程实体（又称进程映像）

4. 就绪态。进程获得了除处理机外的一切所需资源，一旦得到处理机，便可立即运行。等待态或者称为阻塞态，如等待某资源为可用（不包
括处理机）或等待输入/输出完成。即使处理机空闲，该进程也不能运行。

5. 之所以有就绪态和阻塞态的区别，是因为在分时系统的时间片轮转机制中，每个进程分到的时间片是若干毫秒。也就是说，进程得到处理机的时间很短且非常频繁，进程在运行过程中实际上是频繁地转换到就绪态的；而其他资源（如外设）的使用和分配或某一事件的发生（如I/O操作的完成）对应的时间相对来说很长，进程转换到等待态的次数也相对较少

6. 进程主要由 PCB、程序段和数据段三个部分组成。

7. 进程创建时，操作系统为它新建一个PCB,该结构之后常驻内存，任意时刻都可以存取。当操作系统欲调度某进程运行时，要从该进程的PCB中查出其现行状态及优先级。

8. PCB主要包括进程描述信息、进程控制和管理信息、资源分配清单和处理机相关信息等。P38 页

9. 引入进程的目的是更好地使多道程序并发执行，提高资源利用率和系统吞吐量；而引入线程的目的则是减小程序在并发执行时所付出的时空开销，提高操作系统的并发性能。

10. 同一进程中的所有线程都完全共享进程的地址空间和全局变量。各个线程都可以访问进程地址空间的每个单元，所以一个线程可以读、写或甚至清除另一个线程的堆栈。

11. 一个作业可能包含多个进程，尤其在复杂的任务或者需要并行处理多个子任务的情况下。一个进程可以包含一个或多个线程。线程允许进程内的任务并发执行，提高效率。

12. 一个作业可能包含多个进程，尤其在复杂的任务或者需要并行处理多个子任务的情况下。一个进程可以包含一个或多个线程。线程允许进程内的任务并发执行，提高效率。所以，我们需要一些调度算法。

13. 一个作业从提交到开始完成，往往要经历下面的三级调度（从不同层次上的调度算法）

- 高级调度（作业调度）。按照一定的原则从外存上位于后备队列中的作业中挑选一个，然后给他们分配内存、输入和输出设备等资源。作业调度就是内存与辅存之间的调度。每个作业只调入一次、调出一次。（多道批处理系统中大多配有作业调度，而其他系统中通常不需要配置作业调度。）
- 中级调度（内存调度）。引入中级调度的目的是提高内存利用率和系统吞吐量。将那些暂时不能运行的进程调至外存等待，此时进程的状态称为挂起态。当它们己具备运行条件且内存又稍有空闲时，由中级调度来决定把外存上的那些己具备运行条件的就绪进程再重新调入内存，并修改其状态为就绪态，挂在就绪队列上等待。中级调度实际上是存储器管理中的对换功能。
- 低级调度（进程调度）。按照某种算法从就绪队列中选取一个进程，将处理机分配给它。进程调度是最基本的一种调度，在各种操作系统中都必须配置这级调度。进程调度的频率很高，一般几十毫秒一次。

14. 三级调度的联系：作业调度从外存的后备队列中选择一批作业进入内存，为它们建立进程，这些进程被送入就绪队列，进程调度从就绪队列中选出一个进程，并把其状态改为运行态，把CPU分配给它。中级调度是为了提高内存的利用率，系统将那些暂时不能运行的进程挂起来。

15. 进程调度方式主要分为：非抢占调度方式，又称非剥夺方式 和 抢占调度方式，又称剥夺方式。

16. 但是抢占并不是一种任意性的行为，必须遵循一定的原则，主要有优先权、短进程优先和时间片原则等。

17. 有很多典型的进程调度算法，有的适用于作业调度有的适用于进程调度。

- FCFS。先到先服务算法。既可以用于作业调度也可以用于进程调度。这一个算法属于不可剥夺算法，从表面上看，它对所有作业都是公平的，但若一个长作业先到达系统，就会使后面的许多短作业等待很长时间。优点是算法简单，但是效率低
- SJF。短作业优先算法。但是可能会造成长作业饥饿。
- 优先级调度算法。优先级调度算法既可用于作业调度，又可用于进程调度。优先级用于描述紧迫程度。根据是否可以抢占正在执行的进程，可以分为非抢占式优先级调度算法和抢占式优先级调度算法。并且优先级也可以分为静态优先级和动态优先级
- 高响应比优先调度算法。高响应比优先调度算法主要用于作业调度，是对 FCFS 调度算法和 SJF 调度算法的一种综合平衡。其中，定义了响应比的计算公式。
- 时间片轮转调度算法。时间片轮转调度算法主要适用于分时系统。在时间片轮转调度算法中，时间片的大小对系统性能的影响很大。
- 多级队列调度算法。前面的所有调度算法，系统中仅仅设置一个进程的就绪队列，所以调度算法是固定并且单一的，不够灵活。该算法在系统中设置多个就绪队列。

18. 我们将将一次仅允许一个进程使用的资源称为临界资源称作临界资源。

19. 同步亦称直接制约关系。进程间的直接制约关系源于它们之间的相互合作。

20. 互斥也称间接制约关系。

21. 为了禁止两个进程同时进入临界区，同步机制应该遵循以下四个准则：
- 空闲让进。临界区空闲时，应立即让进程进入。
- 忙则等待。当临界区有进程在执行时，其他进程应等待。
- 有限等待。对进程的等待时间应该是有限的。
- 让权等待。当一个进程不能进入临界区时，应立即释放处理机，让其他进程进入。

22. 实现临界区互斥的基本方法，分为软件实现和硬件实现。
- 软件实现有单标志法、双标志先检查、双标志后检查、Peterson's Algo

### 第三章 内存管理

1. 创建进程首先要将程序和数据装入内存。

2. 内存保护的实现：

- 一种方法是，设置一对上、下寄存器，存放用户作业在主存中的上限和下限。
- 动态地将逻辑地址与界地址寄存器进行比较，若未发生地址越界，则加上重定位寄存器的值后映射成物理地址。这里，界地址寄存器存储的是逻辑地址的最大值；基址寄存器含最小的物理地址值

3. 在加载基址寄存器和界址寄存器的时候，需要使用特权指令，只有操作系统内核可以加载这两个寄存器，这保证了不允许用户程序修改寄存器的值。

4. 内存管理的主要功能有：

- 内存空间的分配与回收
- 地址转换
- 内存空间的扩充。利用虚拟存储技术或自动覆盖技术，从逻辑上扩充内存。
- 内存共享。指允许多个进程访问内存的同一部分。例如，多个合作进程可能需要访问同一块数据，因此必须支持对内存共享区域进行受控访问。
- 存储保护。保证各道作业在各自的存储空间内运行，互不干扰。

5. 静态链接和动态链接两者最大的区别就在于链接的时机不一样，静态链接是在形成可执行程序前，而动态链接的进行则是在程序执行时。

6. 为什么要进行静态链接：

在我们的实际开发中，不可能将所有代码放在一个源文件中，所以会出现多个源文件，而且多个源文件之间不是独立的，而会存在多种依赖关系，如一个源文件可能要调用另一个源文件中定义的函数，但是每个源文件都是独立编译的，即每个*.c文件会形成一个*.o文件，为了满足前面说的依赖关系，则需要将这些源文件产生的目标文件进行链接，从而形成一个可以执行的程序。这个链接的过程就是静态链接。

7. #include是用于在编译前将声明和定义插入代码中，而链接则是将所有单独编译的部分（包括库函数的实现）合并成一个可以执行的程序。

当您编译 main.c 文件时，编译器生成的目标文件 main.o 包含了您的代码中定义的函数（如 main）的机器码，以及对外部函数（如 printf）的未解析引用。

这些未解析的引用是指，尽管 main.o 包含对 printf 的调用指令，但它并不包含 printf 函数本身的代码。编译器在生成 main.o 时会在其中放置一个标记，表明 printf 需要在后续步骤中解析。

接器的作用是查看所有输入的目标文件（如 main.o）和库，解析这些未解析的引用。链接器识别到 main.o 中存在对 printf 的调用。

链接器随后搜索链接时指定的库（通常是 C 标准库 libc，如果没有特别指定，编译器会默认使用它）。它在库中找到 printf 的定义，然后将这个定义与 main.o 中的引用“链接”起来，完成引用的解析。

解析完所有引用后，链接器将所有相关的代码和数据合并，生成最终的可执行文件，比如 main.exe 或 a.out。

8. 程序的链接有三种方式：静态链接、装入时动态链接、运行时动态链接

9. 固定分区会产生内部碎片，动态分区会产生外部碎片，这两种技术对内存的利用率都比较低。我们希望内存的使用能尽量避免碎片的产生，这就引入了分页的思想：把主存空间划分为大小相等且固定的块，块相对较小，作为主存的基本单位。每个进程也以块为单位进行划分，进程在执行时，以块为单位逐个申请主存中的块空间。

10. 进程中的块称为页或页面（Page）,内存中的块称为页框或页帧（Page Frame）。外存也以同样的单位进行划分，直接称为块或盘块（Block）。

11. 系统为每个进程建立一张页表，它记录页面在内存中对应的物理块号，页表一般存放在内存中。（注意是，每一个进程都会有页表）

12. 内存分区是早期内存管理的一种形式，其中物理内存被划分为一系列的固定大小或动态大小的区块。内存分页是现代操作系统中使用的主要内存管理技术。它解决了分区带来的内存碎片问题，并支持更复杂的虚拟内存管理。

对于内存分页，物理内存被划分为固定大小的块，称为“物理页”或“页帧”，虚拟内存（程序地址空间）也被划分为同样大小的块，称为“页”，然后通过页表来映射虚拟页到物理页帧。

13. 平时，进程未执行时，页表的始址和页表长度存放在本进程的PCB中，当进程被调度执行时，才将页表始址和页表长度装入页表寄存器中。

14. 页表存储的是 逻辑地址页号到物理地址页帧号（或者说页块号）的映射，所以页表项的长度就是一共有多少页帧的长度。

15. 由上面介绍的地址变换过程可知，若页表全部放在内存中，则存取一个数据或一条指令至少要访问两次内存，显然，这种方法比通常执行指令的速度慢了一半。在地址变换机构中增设一个具有并行查找能力的高速缓冲存储器一一快表，又称相联存储器（TLB）

16. 由于引入了分页管理，进程在执行时不需要将所有页调入内存页框，而只需将保存有映射关系的页表调入内存。

17. 分页管理方式是从计算机的角度考虑设计的，目的是提高内存的利用率，提升计算机的性能

分段管理方式的提出则考虑了用户和程序员，以满足方便编程、信息保护和共享、动态增长及动态链接等多方面的需要。

18. 前面的各种内存管理策略都是为了同时将多个进程保存在内存中，以便允许进行多道程序设计。

19. 内存管理的主要功能有：

- 内存的分配与回收。由操作系统完成主存储器空间的分配和管理，使程序员摆脱存储，分配的麻烦，提高编程效率。
- 地址转换。在多道程序环境下，程序中的逻辑地址与内存中的物理地址不可能一致，因此存储管理必须提供地址变换功能，把逻辑地址转换成相应的物理地址。
- 内存空间的扩充。利用虚拟存储技术或自动覆盖技术，从逻辑上扩充内存。
- 内存共享。指允许多个进程访问内存的同一部分。例如，多个合作进程可能需要访问同一块数据，因此必须支持对内存共享区域进行受控访问。
- 存储保护。保证各道作业在各自的存储空间内运行，互不干扰。

20. 将用户的源程序变为可以在内存中执行的程序，通常需要三个步骤：编译、链接、装入。其中，链接和装入分别都有三种方式。

21. 用户程序和程序员只需知道逻辑地址，而内存管理的具体机制则是完全透明的。

22. 在计算机系统由单道向多道发展时，存储管理方式便由单一连续分配发展为固定分区分配；为了能更好地适应不同大小的程序要求，又从固定分区分配发展到动态分区分配；为了更好地提高内存的利用率，进而从连续分配方式发展到离散分配方式 ———— 页式存储管理；

23. 上下界寄存器进行存储保护和重定位寄存器进行存储保护的时候，前者是对于物理地址直接判断，并且寄存器中也是存储的物理地址，而后者是对于逻辑地址和偏移量的大小进行判断。前者是在用户态下进行的，后者是在核心态下进行的。

24. 在系统中通常设置一个页表寄存器，用来存储页表的其实位置。页表起始位置和页表长度通常存放在进程的 PCB 中。

### 第四章 文件管理

1. 与进程管理一样，为便于文件管理，在操作系统中引入了文件控制块的数据结构。

2. 除了文件本身中的数、据信息，操作系统还会保存文件的相关信息，如所有者，创建时间，这些附加信息称为 文件属性 或文件 元数据。

文件属性通常包括：名称、类型、创建者、所有者、位置、大小、创建时间（类似于 PCB 中的管理信息）

操作系统通过 FCB 来维护文件的元数据

3. 系统通过三个表来维护文件系统的信息：进程级 文件描述符表(file descriptor table)、系统级 打开文件表(open file table)、文件系统 i-node 表(i-node table)

其中，i-node 存储在磁盘设备上，内核在内存中维护了一个副本，这里的 i-node 表为后者。文件描述符表是在进程创建以后，在 PCB 内部存储。

4. 我们每操作一次就找一次名字，这会耗费大量的时间和效率。所以 Linux 中规定每一个文件对应一个索引，这样要操作文件的时候，我们直接找到索引就可以对其进行操作了。这里的索引，就是文件描述符

5. 一个关于讲解文件系统的博文 https://zhuanlan.zhihu.com/p/183238194

6. 磁盘进行读写的最小单位是「扇区」，但是一个扇区的大小只有 521B，所以如果每次读写都这么小的单位，效率会很低。因此，文件系统将多个扇区组成了一个「逻辑块」，Linux 中一个逻辑块的大小为 4KB，也就是一次性读写 8 个扇区。

7. 索引节点，也就是 i-node，用来记录文件的元信息，比如 inode 编号、文件大小、访问权限、创建时间、修改时间、数据在磁盘的位置等等。索引节点是文件的唯一标识，它们之间一一对应，也同样都会被存储在硬盘中，所以索引节点同样占用磁盘空间。（其中，索引节点在硬盘中，并且指向文件在硬盘中的位置）

8. 目录项是文件系统中用于存储文件名与对应索引节点（inode）之间映射的数据结构。是存储在缓存中的，和 i-node 是多对一的关系。

虽然目录项和目录名字很相近，但是它们不是一个东西，目录是个文件，持久化存储在磁盘，而目录项是内核一个数据结构，缓存在内存。如果查询目录频繁从磁盘读，效率会很低，所以内核会把已经读过的目录用目录项这个数据结构缓存在内存，下次再次读到相同的目录时，只需从内存读就可以，大大提高了文件系统的效率。

注意，目录项这个数据结构不只是表示目录，也是可以表示文件的。

9. 它们之间的关系可以是：

- 当一个程序请求打开一个文件时，操作系统首先使用文件名或者路径查找对应的目录项，从而获得文件的索引节点。文件数据可能直接存储在索引节点中（对于很小的文件），或者通过索引节点中的指针间接访问。
- 系统根据索引节点中的信息检查文件访问权限，如果设计打开文件的操作，则在打开文件表中创建一个新的条目，记录文件的操作状态和索引节点信息。
- 操作系统返回一个文件描述符给程序，该文件描述符是打开文件表中条目的索引。应用程序后续的所有操作（如读取、写入、关闭等）都通过这个文件描述符进行。

所以要注意，目录项、索引节点、文件描述符、打开文件表之间的关系。

10. 不过为什么要通过文件索引来将元数据等信息和文件本身分开？？？

11. 目录项和索引节点是多对一的关系，这种情况通常发生在硬链接的场景中。

硬链接是文件系统中的一个特性，它允许一个文件在文件系统中的多个位置有不同的名字（目录项），但这些名字都指向同一个索引节点。实质上，这些目录项都指向同一个文件的数据和元数据。

12. 文件系统中存在硬链接和软链接，硬链接指的是指向文件系统中相同索引节点（inode）的链接。换句话说，硬链接就像是文件的另一个名字。实质就是文件的不同的名字。如果删除了原始文件的一个链接，只要还存在至少一个硬链接，文件数据就仍然存在，因为文件的实际删除是在最后一个硬链接被删除后。

13. 对于访问打开文件表的索引，UNIX称之为文件描述符，而Windows称之为文件句柄。

14. 在多个不同进程可以同时打开文件的操作系统中，通常采用两级表，也就是建立了两级的打开文件表

15. 解决访问控制最常用的方法是根据用户身份进行控制，可以使用简的访问列表（Access-Control List, ACL）来解决这一个问题

文件主在创建文件时，说明创建者用户名及所在的组名，系统在创建文件时也将文件主的名字、所属组名列在该文件的FCB中。用户访问该文件时，若用户是文件主，按照文件主所拥有的权限访问文件；若用户和文件主在同一个用户组，则按照同组权限访问，否则只能按其他用户权限访问。

#### 第一代计算机：真空管和穿孔卡片

第一代计算机的产生是由机械时代进入电子时代的标志，第二次世界大战刺激了有关计算机研究的爆炸性进展。

#### 第二代计算机：晶体管和批处理系统

当时计算机很昂贵，自然想减少机时的浪费，通常采用的就是批处理系统（Batch System）。

用户将作业交给系统操作员，系统操作员将许多用户的作业组成一批作业（job）之后输入到计算机中。在系统中形成一个自动转接的连续的作业流。最后，由操作员将作业结果交给用户。

#### 第三代计算机：集成电路芯片和多道程序设计

多道技术的实现是为了解决多个程序竞争或者说共享一个资源（比如 CPU）的有序调度问题，解决方式基多路复用，分为时间和空间上的复用。

1. 时间上的复用。一个程序进行 IO 的时候，CPU 执行另一个程序
2. 空间上的复用。同一时间多个程序进入内存，硬件层面提供保护机制来确保各自的内存是分割开的，且由操作系统来操控，这样不需要一个一个程序排队进入内存。

分时系统（Time Sharing System）。在分时系统中，计算机会轮流为多个用户提供服务，每个用户似乎都在独占地使用整个系统。这是通过快速地在不同用户之间进行切换来实现的，使得每个用户都感觉到自己在独占使用系统（感觉类似于现在的服务器，多人使用）。

它将 CPU 时间划分为若干个片段，称为「时间片」（time slice）。操作系统以时间片为单位，轮流为每个终端用户提供服务。

#### Computer Startup

启动的四个阶段：

1. BIOS
    随着 ROM（Read-Only Memory，ROM）发明，开机程序被刷入 ROM 芯片，计算机通电以后，第一件事就是执行它，这块 ROM 芯片里面的程序叫做「基本输入输出系统」（Basic Input/Output System），简称 BIOS。
2. 硬件自检
    BIOS 首先检查硬件，开是否符合开机的基本条件，叫做「硬件自检」（Power-On Self Test，POST）。如果硬件出现问题，主板会发出不同含义的蜂鸣。自检完成以后。BIOS 将控制权交给下一个阶段的启动程序。
3. 主引导记录
    BIOS 按照启动顺序，把控制权交给排在第一位的存储设备。
    这时，计算机读取该设备的第一个扇区，也就是读取最前面的512个字节。如果这512个字节的最后两个字节是0x55和0xAA，表明这个设备可以用于启动；如果不是，表明设备不能用于启动，控制权于是被转交给"启动顺序"中的下一个设备。
    最前面的 512 个字节叫做「主引导记录」（Master Boot Record，MBR）
    其中，"主引导记录"只有512个字节，放不了太多东西。它的主要作用是，告诉计算机到硬盘的哪一个位置去找操作系统。
    主引导记录的三个组成部分：
    1. 1-446. 调用操作系统的操作码
    2. 447-510. 分区表（Partition table）
    3. 511-512. 主引导记录签名（0x55 和 0xAA）
    其中，分区表是 64 位，里面又分为 4 项，每一项是 16 字节。所以，一个硬盘最多分为 4 个一级分区，又叫做「主分区」？？？
4. 硬盘启动
    这时，计算机的控制权交给某一个分区，这里又分为三种情况
    1. 卷引导记录
        四个主分区里面，只有一个是激活的。计算机会读取激活分区的第一个扇区，叫做"卷引导记录"（Volume boot record，缩写为VBR）。
    2. 扩展分区和逻辑分区
        随着硬盘越来越大，四个主分区已经不够了，需要更多的分区。但是，分区表只有四项，因此规定有且仅有一个区可以被定义成"扩展分区"（Extended partition）。
        所谓"扩展分区"，就是指这个区里面又分成多个区。这种分区里面的分区，就叫做"逻辑分区"（logical partition）。
    3. 启动管理器
        在这种情况下，计算机读取"主引导记录"前面446字节的机器码之后，不再把控制权转交给某一个分区，而是运行事先安装的"启动管理器"（boot loader），由用户选择启动哪一个操作系统。
5. 操作系统
    控制权被交给操作系统，操作系统的内核首先被载入内存。

> 在计算机启动过程中，BIOS会执行自检（POST），然后检查存储设备，找到可引导的设备。接着，它会读取该设备的主引导记录（MBR）（如果我们是 Windows 系统，这一个 MBR 独立于任何C、D、E类的盘），根据不同的盘搜索引导标记，并将控制权转交给含有引导标记的分区。这个分区中存储着引导加载程序（bootloader），它会加载操作系统的核心文件到内存中，并将控制权传递给操作系统，从而启动了操作系统。

1. 在共享内存中，即使是创建共享内存的进程结束了，别的进程还是可以访问到这个共享内存，共享内存仍然存在，直到被显式删除或系统重启。这是因为共享内存是由操作系统管理的，它的生命周期独立于创建它的进程。这种特性使得共享内存非常适合用于进程间通信，即使这些进程的生命周期不同步。共享内存段的存在不依赖于任何特定的进程。

2. key_t key = ftok("shmfile",65); 这个函数是用来生成一个 key 的，这个 key 是用来标识一个共享内存段的，这个 key 是唯一的，不同的 key 对应不同的共享内存段。ftok 函数的第一个参数是一个文件名，第二个参数是一个整数，这个整数是一个标识符，用来区分不同的共享内存段。ftok 函数会根据这两个参数生成一个 key。

3. shmid 创建共享内存的时候，返回的是一个共享内存的标识符，这个标识符是一个整数，用来标识一个共享内存段。这个标识符是唯一的，不同的共享内存段对应不同的标识符。我们可以通过这个标识符来访问共享内存段。

int shmid = shmget(key, 1024, 0666|IPC_CREAT) 1024 是共享内存的字节大小，0666 是共享内存的权限，IPC_CREAT 表示如果共享内存不存在就创建它。

4. shmat将共享内存段附加到调用进程的地址空间。返回值是指向共享内存第一个字节的指针。

char *str = (char*)shmat(shmid, (void*)0, 0); shmid 是共享内存的地址，(void*)0 通常设置为 0，让系统选择内存段的地址。最后的 0 附加选项，通常设置为 0
 
5. strncpy 将字符串复制到共享内存中。

strncpy 是一个 C 标准库中用于字符串复制的一个函数，与 strcpy 相比，允许设定一个最大的复制长度，从而可以防止缓冲区溢出。

char *strncpy(char *dest, const char *src, size_t n);

dest 是目标字符串的指针，用于存放被复制的字符串。src 是源字符串的指针，用于指定要复制的字符串。n 是最大的复制长度，即最多复制 n 个字符。并且返回一个指向目标字符串的指针。

6. 单纯的 shmdt 只会将共享内存从当前进程的地址空间中分离，并不会销毁共享内存。

7. 使用命令 ipcs -m 可以观察共享内存的情况

8. POSIX 信号量和 System V 信号量之间的关系和区别？

9. 我们可以使用命令 ipcs -m 观察共享内存的情况，ipcs -s 观察信号量数组的情况，ipcs -q 观察消息队列的情况

10. ipcs 和 ipcs -a 可以查看当前系统的所有的 ipc 对象资源。在权限允许的情况下，我们可以使用 ipcrm 命令删除当前系统中存在的 IPC 对象中任意一个对象。

11. 临时虚拟文件。Linux 在运行的时候，在根目录下创建了一个临时目录 /proc。/proc 是一个伪文件系统，只存在内存中，而不占用外存空间。以文件系统的方式为访问系统内核数据的操作提供接口。用户和应用程序可以通过访问proc 中相关的文件得到系统的信息，并可以改变内核的某些参数。
