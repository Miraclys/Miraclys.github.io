### 操作系统发展史

#### 第一代计算机：真空管和穿孔卡片

第一代计算机的产生是由机械时代进入电子时代的标志，第二次世界大战刺激了有关计算机研究的爆炸性进展。

此时，没有操作系统的概念，所有的程序设计都是直接操控硬件。程序员将拿着插板到机房里，几个小时独享计算机资源。程序是串行的。

#### 第二代计算机：晶体管和批处理系统

当时计算机很昂贵，自然想减少机时的浪费，通常采用的就是批处理系统（Batch System）。

用户将作业交给系统操作员，系统操作员将许多用户的作业组成一批作业（job）之后输入到计算机中。在系统中形成一个自动转接的连续的作业流。最后，由操作员将作业结果交给用户。

#### 第三代计算机：集成电路芯片和多道程序设计

多道技术的实现是为了解决多个程序竞争或者说共享一个资源（比如 CPU）的有序调度问题，解决方式基多路复用，分为时间和空间上的复用。

1. 时间上的复用。一个程序进行 IO 的时候，CPU 执行另一个程序
2. 空间上的复用。同一时间多个程序进入内存，硬件层面提供保护机制来确保各自的内存是分割开的，且由操作系统来操控，这样不需要一个一个程序排队进入内存。

分时系统（Time Sharing System）。在分时系统中，计算机会轮流为多个用户提供服务，每个用户似乎都在独占地使用整个系统。这是通过快速地在不同用户之间进行切换来实现的，使得每个用户都感觉到自己在独占使用系统（感觉类似于现在的服务器，多人使用）。

它将 CPU 时间划分为若干个片段，称为「时间片」（time slice）。操作系统以时间片为单位，轮流为每个终端用户提供服务。

#### 第四代计算机：个人计算机（PC）

个人计算机（Personal Computer，PC）

#### Computer Startup

启动的四个阶段：

1. BIOS
    随着 ROM（Read-Only Memory，ROM）发明，开机程序被刷入 ROM 芯片，计算机通电以后，第一件事就是执行它，这块 ROM 芯片里面的程序叫做「基本输入输出系统」（Basic Input/Output System），简称 BIOS。
2. 硬件自检
    BIOS 首先检查硬件，开是否符合开机的基本条件，叫做「硬件自检」（Power-On Self Test，POST）。如果硬件出现问题，主板会发出不同含义的蜂鸣。自检完成以后。BIOS 将控制权交给下一个阶段的启动程序。
3. 主引导记录
    BIOS 按照启动顺序，把控制权交给排在第一位的存储设备。
    这时，计算机读取该设备的第一个扇区，也就是读取最前面的512个字节。如果这512个字节的最后两个字节是0x55和0xAA，表明这个设备可以用于启动；如果不是，表明设备不能用于启动，控制权于是被转交给"启动顺序"中的下一个设备。
    最前面的 512 个字节叫做「主引导记录」（Master Boot Record，MBR）
    其中，"主引导记录"只有512个字节，放不了太多东西。它的主要作用是，告诉计算机到硬盘的哪一个位置去找操作系统。
    主引导记录的三个组成部分：
    1. 1-446. 调用操作系统的操作码
    2. 447-510. 分区表（Partition table）
    3. 511-512. 主引导记录签名（0x55 和 0xAA）
    其中，分区表是 64 位，里面又分为 4 项，每一项是 16 字节。所以，一个硬盘最多分为 4 个一级分区，又叫做「主分区」？？？
4. 硬盘启动
    这时，计算机的控制权交给某一个分区，这里又分为三种情况
    1. 卷引导记录
        四个主分区里面，只有一个是激活的。计算机会读取激活分区的第一个扇区，叫做"卷引导记录"（Volume boot record，缩写为VBR）。
    2. 扩展分区和逻辑分区
        随着硬盘越来越大，四个主分区已经不够了，需要更多的分区。但是，分区表只有四项，因此规定有且仅有一个区可以被定义成"扩展分区"（Extended partition）。
        所谓"扩展分区"，就是指这个区里面又分成多个区。这种分区里面的分区，就叫做"逻辑分区"（logical partition）。
    3. 启动管理器
        在这种情况下，计算机读取"主引导记录"前面446字节的机器码之后，不再把控制权转交给某一个分区，而是运行事先安装的"启动管理器"（boot loader），由用户选择启动哪一个操作系统。
5. 操作系统
    控制权被交给操作系统，操作系统的内核首先被载入内存。

> 在计算机启动过程中，BIOS会执行自检（POST），然后检查存储设备，找到可引导的设备。接着，它会读取该设备的主引导记录（MBR）（如果我们是 Windows 系统，这一个 MBR 独立于任何C、D、E类的盘），根据不同的盘搜索引导标记，并将控制权转交给含有引导标记的分区。这个分区中存储着引导加载程序（bootloader），它会加载操作系统的核心文件到内存中，并将控制权传递给操作系统，从而启动了操作系统。

### 第一章 计算机系统概述

1. 操作系统是什么：

操作系统(Operating System, OS)是指控制和管理整个计算机系统的硬件与软件资源，合理地组织、调度计算机的工作与资源的分配，进而为用户和其他软件提供方便接口与环境的程序集合。

2. 并发指的是同一个时间间隔内有多个事件发生，而并行指的是同一时刻多个事件发生。所以可以理解为，并发是宏观上多个程序一起执行，微观上一个时间点只有一个程序在执行；并行是宏观上多个程序一起执行，微观上多个程序在同时执行。

3. 操作系统中共享的资源主要分为两种：1. 互斥共享方式 2. 同时访问方式（P02）

4. 操作系统的发展历程：

- 手工操作阶段，所有工作都需要人工干预，虽然是用户独占全机，但是资源利用率低，而且 CPU 需要手工操作，CPU 的利用不充分。
- 批处理操作系统（操作系统开始出现），又分为单道批处理系统和多道批处理系统。
    单道批处理系统：系统对作业是成批处理的，但是内存中始终保持一道作业。单道批处理系统中，每次主机内存中仅保存一道作业，每次在运行时，发出输入、输出请求，高速的 CPU 需要等待低俗的 IO 完成操作。
    多道批处理系统：多道程序设计技术允许多个程序同时进入内存并允许它们在CPU中交替地运行。当一道程序因I/O请求而暂停运行时，CPU便立即转去运行另一道程序。
    多道程序设计的特点是多道、宏观上并行、微观上串行。
    多道程序设计的缺点：不提供人机交互能力，用户既不能了解自己的程序的运行情况，又不能控制计算机。
- 分时操作系统，指把处理器的运行时间分成很短的时间片，按时间片轮流把处理器分配给各联机作业使用。分时操作系统是指多个
用户通过终端同时共享一台主机，这些终端连接在主机上，用户可以同时与主机进行交互操作而互不干扰。所以说，分时操作系统解决了人机交互的问题，
- 实时操作系统，为了能在某个时间限制内完成某些紧急任务而不需要时间片排队，诞生了实时操作系统。
- 个人操作系统

5. 特权指令：不允许用户直接使用的指令，如I/O指令、置中断指令，存取用于内存保护的寄存器、送程序状态字到程序状态字寄存器等的指令

非特权指令：不能直接访问系统中的软硬件资源，仅限于访问用户的地址空间

CPU 处于核心态，此时 CPU 可以执行特权指令，切换到用户态的指令也是特权指令。

6. 原语是一些可以被调用的公用小程序，通常运行时间都较短，而且调用频繁。

7. 系统调用：用户程序想要获得操作系统中的资源

系统中的各种共享资源都由操作系统统一掌管，因此在用户程序中，凡是与资源有关的操作（如存储分配、进行I/O传输及管理文件等），都必须通过系统调用方式向操作系统提出服务请求，并由操作系统代为完成。

系统调用的相关功能需要使用某些特权指令才能完成，所以系统调用的处理需要由操作系统内核程序负责完成，要运行在核心态

8. CPU 通常执行两种不同类型的程序：操作系统内核程序 和 用户程序。

9. 当需要管理程序服务时，系统则通过硬件中断机制进入核心态。（需要中断，切换 CPU 的模式）

10. 若程序的运行由用户态转到核心态，则会用到访管指令，访管指令是在用户态使用，所以它不是特权指令。

11. CPU运行上层程序时唯一能进入这些 “门（指的是切换 CPU 模式）” 的途径就是通过中断或异常。

12. 从操作系统内核架构来划分，可以分为宏内核和微内核。

宏内核：将系统的主要功能模块都作为一个紧密联系的整体运行在核心态，从而为用户程序提供高性能的系统服务。因为各管理模块之
间共享信息，能有效利用相互之间的有效特性，所以具有无可比拟的性能优势。

微内核：是指将内核中最基本的功能保留在内核，而将那些不需要在核心态执行的功能移到用户态执行。微内核结构将操作系统划分为两大部分：微内核和多个服务器只有微内核运行在内核态，其余模块都运行在用户态，一个模块中的错误只会使这个模块崩溃，而不会使整个系统崩溃。

### 第二章 进程与线程

1. 在多道程序环境下，允许多个程序并发执行，此时它们将失去封闭性，并具有间断性及不可再现性的特征，因此我们引入了进程的概念。

2. 系统利用PCB来描述进程的基本情况和运行状态，进而控制和管理进程。

3. 程序段、相关数据段和PCB三部分构成了进程实体（又称进程映像）

4. 就绪态。进程获得了除处理机外的一切所需资源，一旦得到处理机，便可立即运行。等待态或者称为阻塞态，如等待某资源为可用（不包
括处理机）或等待输入/输出完成。即使处理机空闲，该进程也不能运行。

5. 之所以有就绪态和阻塞态的区别，是因为在分时系统的时间片轮转机制中，每个进程分到的时间片是若干毫秒。也就是说，进程得到处理机的时间很短且非常频繁，进程在运行过程中实际上是频繁地转换到就绪态的；而其他资源（如外设）的使用和分配或某一事件的发生（如I/O操作的完成）对应的时间相对来说很长，进程转换到等待态的次数也相对较少

6. 进程主要由 PCB、程序段和数据段三个部分组成。

7. 进程创建时，操作系统为它新建一个PCB,该结构之后常驻内存，任意时刻都可以存取。当操作系统欲调度某进程运行时，要从该进程的PCB中查出其现行状态及优先级。

8. PCB主要包括进程描述信息、进程控制和管理信息、资源分配清单和处理机相关信息等。P38 页

9. 引入进程的目的是更好地使多道程序并发执行，提高资源利用率和系统吞吐量；而引入线程的目的则是减小程序在并发执行时所付出的时空开销，提高操作系统的并发性能。

10. 同一进程中的所有线程都完全共享进程的地址空间和全局变量。各个线程都可以访问进程地址空间的每个单元，所以一个线程可以读、写或甚至清除另一个线程的堆栈。

11. 一个作业可能包含多个进程，尤其在复杂的任务或者需要并行处理多个子任务的情况下。一个进程可以包含一个或多个线程。线程允许进程内的任务并发执行，提高效率。

12. 一个作业可能包含多个进程，尤其在复杂的任务或者需要并行处理多个子任务的情况下。一个进程可以包含一个或多个线程。线程允许进程内的任务并发执行，提高效率。所以，我们需要一些调度算法。

13. 一个作业从提交到开始完成，往往要经历下面的三级调度（从不同层次上的调度算法）

- 高级调度（作业调度）。按照一定的原则从外存上位于后备队列中的作业中挑选一个，然后给他们分配内存、输入和输出设备等资源。作业调度就是内存与辅存之间的调度。每个作业只调入一次、调出一次。
- 中级调度（内存调度）。引入中级调度的目的是提高内存利用率和系统吞吐量。将那些暂时不能运行的进程调至外存等待，此时进程的状态称为挂起态。当它们己具备运行条件且内存又稍有空闲时，由中级调度来决定把外存上的那些己具备运行条件的就绪进程再重新调入内存，并修改其状态为就绪态，挂在就绪队列上等待。中级调度实际上是存储器管理中的对换功能。
- 低级调度（进程调度）。按照某种算法从就绪队列中选取一个进程，将处理机分配给它。进程调度是最基本的一种调度，在各种操作系统中都必须配置这级调度。进程调度的频率很高，一般几十毫秒一次。

14. 三级调度的联系：作业调度从外存的后备队列中选择一批作业进入内存，为它们建立进程，这些进程被送入就绪队列，进程调度从就绪队列中选出一个进程，并把其状态改为运行态，把CPU分配给它。中级调度是为了提高内存的利用率，系统将那些暂时不能运行的进程挂起来。

15. 进程调度方式主要分为：非抢占调度方式，又称非剥夺方式 和 抢占调度方式，又称剥夺方式。

16. 但是抢占并不是一种任意性的行为，必须遵循一定的原则，主要有优先权、短进程优先和时间片原则等。

17. 有很多典型的进程调度算法，有的适用于作业调度有的适用于进程调度。

- FCFS。先到先服务算法。既可以用于作业调度也可以用于进程调度。这一个算法属于不可剥夺算法，从表面上看，它对所有作业都是公平的，但若一个长作业先到达系统，就会使后面的许多短作业等待很长时间。优点是算法简单，但是效率低
- SJF。短作业优先算法。但是可能会造成长作业饥饿。
- 优先级调度算法。优先级调度算法既可用于作业调度，又可用于进程调度。优先级用于描述紧迫程度。根据是否可以抢占正在执行的进程，可以分为非抢占式优先级调度算法和抢占式优先级调度算法。并且优先级也可以分为静态优先级和动态优先级
- 高响应比优先调度算法。高响应比优先调度算法主要用于作业调度，是对 FCFS 调度算法和 SJF 调度算法的一种综合平衡。其中，定义了响应比的计算公式。
- 时间片轮转调度算法。时间片轮转调度算法主要适用于分时系统。在时间片轮转调度算法中，时间片的大小对系统性能的影响很大。
- 多级队列调度算法。前面的所有调度算法，系统中仅仅设置一个进程的就绪队列，所以调度算法是固定并且单一的，不够灵活。该算法在系统中设置多个就绪队列。

18. 我们将将一次仅允许一个进程使用的资源称为临界资源称作临界资源。

19. 同步亦称直接制约关系。进程间的直接制约关系源于它们之间的相互合作。

20. 互斥也称间接制约关系。

21. 为了禁止两个进程同时进入临界区，同步机制应该遵循以下四个准则：
- 空闲让进。临界区空闲时，应立即让进程进入。
- 忙则等待。当临界区有进程在执行时，其他进程应等待。
- 有限等待。对进程的等待时间应该是有限的。
- 让权等待。当一个进程不能进入临界区时，应立即释放处理机，让其他进程进入。

22. 实现临界区互斥的基本方法，分为软件实现和硬件实现。
- 软件实现有单标志法、双标志先检查、双标志后检查、Peterson's Algo
- 硬件实现方法。计算机提供了特殊的硬件指令，允许对一个字中的内容进行检测和修正，或对两个字的内容进行交换等。

23. 其中，上面的硬件实现方法
- 中断屏蔽方法。当一个进程正在执行它的临界区代码时，防止其他进程进入其临界区的最简方法是关中断。因为CPU只在发生中断时引起进程切换。但是这种方式限制了处理机交替执行程序的能力，因此执行的效率会明显降低。
- 硬件指令方法。TestAndSet 指令这一条指令是原子操作。Swap 指令也是原子操作，它们都是由硬件逻辑直接实现的，不会被中断。这两种指令否可以实现硬件的互斥。

24. 硬件指令的优点：适用于任意数目的进程，而不管是单处理机还是多处理机；简单、容易验证其正确性。

硬件指令的缺点：进程等待进入临界区时要耗费处理机时间，不能实现让权等待。从等待进程中随机选择一个进入临界区，有的进程可能一直选不上，从而导致"饥饿”象。（因为可以从实例程序中看到，我们是一直在 while 循环检测 lock 的值的，所以并没有释放 CPU）

1. 在共享内存中，即使是创建共享内存的进程结束了，别的进程还是可以访问到这个共享内存，共享内存仍然存在，直到被显式删除或系统重启。这是因为共享内存是由操作系统管理的，它的生命周期独立于创建它的进程。这种特性使得共享内存非常适合用于进程间通信，即使这些进程的生命周期不同步。共享内存段的存在不依赖于任何特定的进程。

2. key_t key = ftok("shmfile",65); 这个函数是用来生成一个 key 的，这个 key 是用来标识一个共享内存段的，这个 key 是唯一的，不同的 key 对应不同的共享内存段。ftok 函数的第一个参数是一个文件名，第二个参数是一个整数，这个整数是一个标识符，用来区分不同的共享内存段。ftok 函数会根据这两个参数生成一个 key。

3. shmid 创建共享内存的时候，返回的是一个共享内存的标识符，这个标识符是一个整数，用来标识一个共享内存段。这个标识符是唯一的，不同的共享内存段对应不同的标识符。我们可以通过这个标识符来访问共享内存段。

int shmid = shmget(key, 1024, 0666|IPC_CREAT) 1024 是共享内存的字节大小，0666 是共享内存的权限，IPC_CREAT 表示如果共享内存不存在就创建它。

4. shmat将共享内存段附加到调用进程的地址空间。返回值是指向共享内存第一个字节的指针。

char *str = (char*)shmat(shmid, (void*)0, 0); shmid 是共享内存的地址，(void*)0 通常设置为 0，让系统选择内存段的地址。最后的 0 附加选项，通常设置为 0
 
5. strncpy 将字符串复制到共享内存中。

strncpy 是一个 C 标准库中用于字符串复制的一个函数，与 strcpy 相比，允许设定一个最大的复制长度，从而可以防止缓冲区溢出。

char *strncpy(char *dest, const char *src, size_t n);

dest 是目标字符串的指针，用于存放被复制的字符串。src 是源字符串的指针，用于指定要复制的字符串。n 是最大的复制长度，即最多复制 n 个字符。并且返回一个指向目标字符串的指针。
