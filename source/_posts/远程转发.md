现在有一个状况，校园网内实验室有一台主力机，并且我有一个笔记本和拥有公网 IP 的服务器。一些东西没有办法直接在笔记本上跑，所以说需要连接到实验室的电脑。虽然在校园内的时候，因为都是连接的校园网，随时随地都可以连接到实验室的电脑，但是一旦离开校园，就没有办法连接到实验室的电脑了。所以说，我需要一种方法，可以在离开校园的时候，也可以连接到实验室的电脑。

为了实现这种操作好像可以借助现有的内网穿透工具，但是也可以使用 ssh 的远程转发功能。这里我选择使用 ssh 的远程转发功能。

#### 远程转发

首先，远程转发的命令是 ssh -R 远程端口:本地地址:本地端口 服务器用户名@服务器远程地址。它的含义是，将访问远程的对应IP下对应用户名的对应端口的流量，转发到本地对应的端口。所以说，如果我们先在实验室的电脑上运行这个命令，使其远程转发发送到公网服务器的对应流量，就可以实现在离开校园的时候，连接到实验室的电脑。

具体来说，如果我们想将公网服务器上访问 2345 端口的流量转发到实验室的电脑的 22 端口（因为 ssh 连接到默认端口就是 22），那么我们可以在实验室的电脑上运行如下命令：ssh -CNR 2345:localhost:22 用户名@公网服务器的 IP。这样，我们可以在笔记本上运行命令 ssh -p 2345 实验室用户名@服务器远程地址，就可以连接到实验室的电脑了。

其中，ssh 的命令中，-N 表示 SSH 不执行远程命令，这通常与隧道一起使用，当我们不需要在 SSH 会话中运行命令的时候，只设置隧道非常有用。-C 表示压缩数据传输，可以加快在 SSH 会话中数据的传输速度，特别是在传输大量数据时，这非常有用。

#### ssh 相关配置修改

一般来说，好像进行了上面的操作以后，还是无法直接连接实验室的电脑，我们需要修改一下 ssh 的配置文件。在实验室的电脑上，我们需要修改 /etc/ssh/sshd_config 文件，将其中的 GatewayPorts 选项设置为 yes。这样，我们就可以在笔记本上直接连接到实验室的电脑了。

其中，GatewayPorts 配置项控制 SSH 隧道中远程转发的行为，默认情况下，转发的端口只能在远程服务器上被 localhost 访问，如果设置了 GatewayPorts 为 yes，那么远程转发的端口就可以被其他主机访问了。

虽然现在连接了，我发现连接很不稳定，会经常断掉。我们可以修改一些 ssh 配置项来解决这一个问题。

ClientAliveInterval 设置服务器端向客户端发送消息的频率，以秒为单位，默认为 0，表示不发送。如果设置为非零值，当连接中断的时候，系统可以自动断开会话，避免「僵尸」连接。ClientAliveCountMax 设置服务器端向客户端发送消息的次数，如果超过这个次数，服务器端就会断开连接。我们可以将这两个配置项设置为一个合适的值，来保持连接的稳定。
